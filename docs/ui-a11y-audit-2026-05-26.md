## Findings & remediation by audit category

### 1. Focus visibility (WCAG 2.4.7)

**问题**：4 处 `:focus-visible` 规则中 `outline: none` 后未做替代恢复，导致键盘用户看不到焦点。

| 文件:行 | 修复方案 |
|---------|----------|
| `src/components/layout/HeroSection.astro:200` | 加 `outline: 2px solid var(--color-accent); outline-offset: 2px;` |
| `src/components/layout/SplashNav.astro:221` | 同上 |
| `src/styles/blood-b32.css:153` | 新增 `:focus-visible` 规则（sakura mode 用 sakura-deep 替代 accent） |
| `src/styles/starlight-override.css:194` | 同上 |

**Explore agent 误报复核（保留原状）**：
- `DrugCards.tsx:129` + `:301`：`outline: none` 与 `:focus-visible { outline: 2px... }` 配对，是合规的"鼠标无环、键盘有环"模式
- `DrugBrandIndex.tsx:470`：同上
- `TrustPillars.astro:408`：`box-shadow` 在 `.trust-pillar__icon` 上，非交互元素

### 2. Touch targets (WCAG 2.5.5)

**问题**：EmergencyBanner CTA 文字链接 `padding: var(--space-xs) var(--space-md)` ≈ 4×16px，实际可点高度 ~20px，远低于 44px。

**修复**：`src/components/ui/EmergencyBanner.astro:90-103` — 加 `display: inline-flex; align-items: center; min-height: 44px; padding: var(--space-sm) var(--space-md)`。

**前次审计 P0-3 复核**：
- ReferenceLibrary.tsx tabs minHeight: 44px ✅
- BloodTestChecker.tsx input + clearBtn minHeight: 44px ✅
- DrugBrandIndex.tsx badge 是非交互 `<span>` ✅

### 3. Skip-to-main-content (WCAG 2.4.1)

**问题**：Starlight 的 `Page.astro` 已渲染 `<SkipLink/>`（验证：`node_modules/@astrojs/starlight/components/SkipLink.astro` 来自 `virtual:starlight/components/SkipLink`）。但项目自定义的 `src/layouts/BlogPostLayout.astro`（被 `src/pages/zh/blog/[slug].astro` 使用）无 skip-link。

**修复**：
- `BlogPostLayout.astro:139` — `<a href="#blog-main-content" class="blog-skip-link">` 作为 body 第一个元素
- `<main>` 加 `id="blog-main-content"`
- sr-only 样式（`clip rect 0 0 0 0` + `width:1px;height:1px`）+ `:focus` 展开到左上角
- `src/i18n/ui.ts` 4 语言加 `a11y.skipToMain` 键

### 4. FloatingAIChat — modal a11y (WCAG 2.1.2 / 2.3.3 / 2.4.3 / 4.1.2)

**问题**：
- 无 Escape 关闭
- 无 focus management
- 内联 `@keyframes` 无 `prefers-reduced-motion` 退化
- 容器无 `role="dialog"` 

**修复**（`src/components/interactive/FloatingAIChat.tsx`）：
- `useRef` 持有 `fabRef` + `panelRef`
- `useEffect` 监听 `document.keydown` Escape → `handleClose()`
- `handleClose()` 回调 `fabRef.current?.focus()` 返回触发器（focus order）
- 打开时 `useEffect` 自动聚焦面板第一个 focusable
- 面板容器加 `role="dialog" aria-modal="true" aria-label="AI 问答助手"`
- FAB 加 `aria-haspopup="dialog" aria-expanded={isOpen}`
- `<style>` 内 `@media (prefers-reduced-motion: reduce)` 把 transform 动画退化为 opacity-only

### 5. Form validation a11y (WCAG 4.1.2 / 3.3.1)

**问题**：BloodTestChecker 输入框的"红区"反馈仅靠 label 旁的彩色圆点（视觉），无 `aria-invalid`、无 `aria-describedby`、无屏幕阅读器可感知的状态信息。

**修复**（`src/components/interactive/BloodTestChecker.tsx`）：
- 把嵌套在 JSX 中的 IIFE 提到组件顶部，复用 `level` 变量
- `input` 加 `aria-invalid={isRed || undefined}` + `aria-describedby={statusId}`
- 视觉圆点加 `aria-hidden="true"`
- 新增隐藏 `<span id role="status" aria-live="polite">` 内容随 level 变化为"在目标范围内 / 需注意 / 超出安全范围，需就医评估"

**AIAssistant 复核（Explore agent 误报）**：
- `AIAssistant.tsx:527-530` 已有 `role="log" aria-live="polite" aria-atomic="false" aria-relevant="additions text"` ✅
- `AIAssistant.tsx:613` 已有 `aria-label={ui.inputLabel}` ✅

### 6. Color contrast (WCAG 1.4.3)

**问题**：Explore agent 报告 dark `--color-text-muted: #BFB0C5` on `#0D0B14` = 3.18:1（FAIL）。手算复核为 ~9.5:1 ✅（agent 报告错误）。但 light theme `--color-text-muted: #8A82A0` on `#FAF7FC` 实测 ~3.4:1（确实 FAIL）。

**修复**（`src/styles/global.css:181`）：light theme `#8A82A0` → `#6B6280`（~5.3:1）。Dark theme 不变。

### 7. Mobile breakpoints + iOS safe-area

| 文件 | 修改 |
|------|------|
| `DrugQuickNav.astro:129` | `max-width: 540px` → `max-width: 640px`（375-480px 单列） |
| `DoseSimulator.tsx:656` | `max-width: 540px` → `max-width: 640px` |
| `FloatingAIChat.tsx:14-15` | `bottom: '24px'` → `bottom: 'max(24px, calc(env(safe-area-inset-bottom, 0px) + 16px))'`；`right` 同理用 env() |
